# Линия спорта × МойСклад

Приватная интеграция создания **заказов покупателей** (`customerorder`) и **заказов поставщикам** (`purchaseorder`) через официальный [JSON API 1.2](https://dev.moysklad.ru/doc/api/remap/1.2/) и GitHub Actions. На существующий REG.RU Host-Lite ничего устанавливать не нужно.

**Статус:** исходники установлены; реальное подключение требует отдельного нового токена и проверки. До завершения проверки создание документов блокируется. Отправка поставщику через Telegram остаётся ручной.

## Подключение

1. Отозвать прежний токен, отправленный в переписку. Выпустить новый токен в МойСклад (желательно под отдельной учётной записью с минимальными правами).
2. [Settings → Secrets and variables → Actions](https://github.com/lsevmos-gpt/ls-moysklad/settings/secrets/actions) → вкладка **Secrets** → **New repository secret**. Имя: `MOYSKLAD_TOKEN`, значение: **новый** токен (только в защищённом поле, не в чате).
3. На этой же странице вкладка **Variables** → **New repository variable**, имя `MOYSKLAD_WRITE_ENABLED`, значение **NO**. **Не включать YES до тестирования реального чтения.**
4. [Settings → Actions → General](https://github.com/lsevmos-gpt/ls-moysklad/settings/actions) → разрешить запуск Actions. При необходимости настроить для `GITHUB_TOKEN` возможность писать результаты в репозиторий (Workflow permissions: Read and write).
5. Начальный безопасный тест — создать запрос поиска как файл `requests/lookup-products-0001.json`, используя пример из `examples/`. Запрос исполнится через Actions, ответ появится в `results/lookup-products-0001.json`.
6. После проверки реальных товаров и цен можно тестировать предпросмотр заказа без записи. Включение `MOYSKLAD_WRITE_ENABLED=YES` означает разрешение на запись **только подтверждённых заказов**.

## Логика

- `lookup`: чтение товаров, модификаций, услуг, контрагентов, организаций и складов.
- `preview_order`: проверка UUID, просмотр сторон, позиций, количества, цены и суммы; **без POST**.
- `create_order`: только при `confirmed: true`, совпадении `approved_preview_id` и всех полей с одобренным предпросмотром и `MOYSKLAD_WRITE_ENABLED=YES`.
- Каждой заявке нужен уникальный `request_id` длиной 8–60 символов, совпадающий с именем JSON-файла без расширения.
- Сначала разместить запрос просмотра в `requests/`. Когда файл результата появится в `results/`, можно отдельно создать подтверждённый запрос. **Не копировать пример с фиктивными UUID как реальный заказ.**
- Заказы создаются **непроведёнными** (`applicable=false`) с отдельным `externalCode`. Дубли проверяются до записи.
- `results/` содержат итоги для последующего просмотра в ChatGPT; для поставщика — текст, который можно скопировать в Telegram.

## Важно

- Цена явно задаётся в заявке (`price_rub` строка, например `"1290.00"`). Мост её автоматически не меняет; проверь цены перед подтверждением.
- Первая версия **не проверяет остатки по складам** и не резервирует товар; такие проверки можно внедрить позднее.
- Нет оплат, отгрузок, приёмок, списаний или автоматической отправки в Telegram.
- Не клади API-ключи, личные данные покупателей или контакты в JSON-запросы.
- В GitHub Actions выполняются автономные локальные тесты (`python -m unittest discover -s tests -v`).

## Пример порядка работы

1. `examples/01-find-products.json` → запрос `lookup-products-0001`.
2. Найти контрагента (`examples/02-find-suppliers.json`), организацию и склад.
3. `examples/04-preview-customer-order.json` или `examples/06-preview-supplier-order.json` с **реальными UUID** и согласованными ценами.
4. Обсудить предпросмотр и получить отдельное подтверждение пользователя.
5. `examples/05-create-customer-order.json` или `examples/07-create-supplier-order.json` — после включения записи.
