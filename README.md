# Crush-PRO × МойСклад

Самостоятельный проект для управления заказами покупателей и заказами поставщикам от имени **Crush-PRO**. Не использует юридические лица или товарный учёт других проектов.

Интеграция использует официальный [JSON API 1.2 МоегоСклада](https://dev.moysklad.ru/doc/api/remap/1.2/) и GitHub Actions. Для работы API не требуется менять хостинг сайтов.

## Привязка к организации

Действующая организация в аккаунте: **Crush-PRO**, ID: `62774749-69ef-11e7-7a34-5acf0009fff7`.

- Для `customerorder` (заказ покупателя) и `purchaseorder` (заказ поставщику) организация подставляется автоматически.
- Поле `organization_id` в заявке можно **не указывать**.
- Если указана другая организация, создание заказа блокируется, включая стадию предварительного просмотра.
- Контрагент (`agent_id`) и склад (`store_id`) подбираются отдельно из реальных данных базы.
- Технический адрес репозитория пока остаётся `lsevmos-gpt/ls-moysklad`; это историческое имя репозитория, не обозначение заказчика. Для переименования в `crush-pro-moysklad` используйте GitHub **Settings → General → Repository name**. После переименования обновите ссылки в документации.

## Текущее состояние

- Запросы на **чтение** склада, товаров, контрагентов и организации проверены с реальным API.
- В аккаунте обнаружены организация **Crush-PRO** и склад **Основной склад**.
- Создание реального заказа ещё не проверено. По умолчанию запись **запрещена**.
- Telegram-отправка остаётся ручной: формируется текст для копирования.

## Секреты и настройки

1. Прежний токен, отправленный в чат, отзовите. Новый токен сохраните только в [GitHub → Settings → Secrets and variables → Actions](https://github.com/lsevmos-gpt/ls-moysklad/settings/secrets/actions) с именем `MOYSKLAD_TOKEN`. Не записывайте его в запросы.
2. Вкладка **Variables** → переменная `MOYSKLAD_WRITE_ENABLED` = `NO` (либо отсутствие переменной). Значение `YES` разрешает запись только после предварительного просмотра и подтверждения.
3. В [GitHub Actions](https://github.com/lsevmos-gpt/ls-moysklad/actions) можно смотреть результаты выполнения. Для записи `results/` бот должен обладать правами записи в репозиторий.
4. Запросы находятся в `requests/*.json`. Workflow записывает результаты в `results/*.json`; ошибки API отдаются без конфиденциальных заголовков.

## Логика API-моста

- `lookup` — поиск товаров, модификаций, услуг, контрагентов, организаций и складов.
- `preview_order` — сверка UUID контрагента, склада, фактических названий товаров, количества, цен и общей суммы; **без создания документа**.
- `create_order` — только после отдельного явного подтверждения пользователя, `confirmed: true`, `approved_preview_id` и точного совпадения согласованных полей; запись разрешена при `MOYSKLAD_WRITE_ENABLED=YES`.
- Для каждой заявки создаётся уникальный `request_id` (8–60 символов), совпадающий с именем JSON-файла без расширения.
- Заказы записываются **непроведёнными** (`applicable=false`) и получают `externalCode` с префиксом `CPAI-`. Перед записью проверяется наличие дубля.
- Для заказа поставщику дополнительно создаётся `telegram_text`, который можно вручную отправить контрагенту.

## Порядок оформления

1. Найти контрагента в базе через `lookup`, уточнить склад и товары.
2. Создать `preview_order` с корректными `agent_id`, `store_id`, позициями и ценами. Организацию **не указывать** — используется Crush-PRO.
3. Получить и проверить результат предпросмотра из `results/`.
4. После подтверждения пользователя и разрешения записи создать отдельный `create_order` с согласованными параметрами.
5. Сверить номер и сумму созданного документа с МоемСкладом. Текст для Telegram отправляется человеком.

Рабочие шаблоны формата (с фиктивными UUID контрагентов и товаров) — в папке `examples/`. **Не отправляйте их в качестве настоящего заказа.**

## Ограничения

- Цены передаются явно в заявке, например `"price_rub": "1290.00"`, и **не заменяются** автоматически.
- Текущая реализация не контролирует складские остатки и не резервирует товар.
- Оплата, отгрузка, приёмка, списания и отправка в Telegram не выполняются.
- Персональные данные и секреты не должны попадать в `requests/` и `results/`.
- Тесты: `python -m unittest discover -s tests -v`.
